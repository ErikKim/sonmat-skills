# sonmat-read-files — 1. 게임 파일 읽기

게임을 켜지 않고, PC 설치 폴더를 **읽기만** 해서 채운다. 추측하지 말고 파일에서 확인한다. 모르면 검색 먼저.

## 볼 것

| 볼 것 | 어떻게 | 왜 |
|---|---|---|
| 소리 엔진 | 실행 파일·폴더의 문자열(`AK::`, `Wwise`, UE `SoundCue`, `FMOD`, MAME 롬) | 훅·리더를 고른다 |
| 소리 이름 | 게임 파일의 큐 이름, 공개 이름표(`bnnm/wwiser-utils` 의 `wwnames/<게임>.txt`), MAME 은 번호 | 규칙을 이름으로 쓸 수 있는지. 번호뿐이면 일이 몇 배다 |
| 음원 보관 | pak(키 필요?) / 낱개 `.bnk`·`.wsp` / cpk·dat / 롬 | 리더를 고르거나 새로 쓴다(`readers.md`) |
| 입력 방식 | 실행 파일에 `XInputSetState` 만 있으면 XInput 전용 | Steam Input 을 켜야 하고, 그 진동이 우리 햅틱을 막을 수 있다 |
| 실행 파일 보호 | 코드 구역 엔트로피(8.0 근처 = 스팀 포장으로 암호화) | 함수는 켜진 게임의 메모리에서만 찾는다(2단계) |
| 게임 자체 진동 | 패드에 직접 쓰는지(듀얼센스 직접 지원 `bUseWinDualSense` 등), 컷씬 진동 표가 있는지 | 실행 조건 안내. 원래 진동은 로더의 `sonmat_rumble.dll` 이 막고 기록한다 |
| **원래 진동 표** | 아래 절 | **어느 순간이 진동하는가 = 분류 근거.** 3단계 칸 배정과 4단계 빈자리 대조의 입력 |
| 조작·모드·장소 | 버튼 배치, 모드(횡스크롤·비행·해킹·탈것), 스테이지별 탈것·물·눈·늪 | 3단계 `game.json` 의 `_controls_note`·`_places_note`. 이 설치본에서 읽은 것과 일반 지식을 구분해 적는다 |

## 원래 진동 표 찾기
원래 게임이 진동을 어디서 정하는지를 **끝까지** 센다. "코드 안이라 어렵다"로 멈추지 않는다(니어: 처음엔 그렇게 말했지만 rea 로 전부 셀 수 있었다).

1. **데이터에 있는 것**: 문자열 훑기로 먼저 찾는다 — 언리얼 `ForceFeedbackEffect`·몽타주 표식·시퀀스·블루프린트(P의 거짓: 몽타주 142·블루프린트 7·시퀀스 62), Wwise `Motion_*`·`HAP_*` 뱅크 동작(오공 `bnk_motion.json` 628개), 프롬 `rumblebnd` 의 `padRumble.rmb`+동작 파일 `.tae`(세키로), 유니티 `NXRumbles`+`.bnvib`·설정의 `*VibrationFrame`, UE3 패키지의 애니·전투 스크립트·Kismet·영상 표(아캄 `_arkham_rea/`), 컷씬 evn·동작 `VibTrack`(니어). 콘솔판 것까지 본다.
2. **코드에 있는 것**: rea(스킬 `reverse-engineer-anything`)로 실행 파일의 패드 출력(`XInputSetState`, 듀얼센스 보고서 쓰기) → 진동 거는 함수 → **부르는 곳 전부**. 데이터 재생기와 하드코딩(카메라 흔들림, 내 피격 기준값, 특정 적)을 가른다. 결과는 `sonmat-prj/_<게임>_rea/` 에 둔다.
3. **없는 것도 적는다**: 원래 게임이 진동하지 않는 내 동작(니어 = 내 공격 명중·회피·저스트 회피·포드 사격·발소리)은 우리 진동이 채우는 자리다.
4. 표는 `sonmat-video/data/rumble_research/<게임>_*.json` 에, 요약은 `intake.md` 6절에. 파형·세기 값은 가져다 쓰지 않는다 — 시각·길이·순간만.

## 소리가 무엇인지 (이름 쪽)
- 이름이 읽히면 이름으로 분류한다. 번호뿐이면 `readers.md` 와 `sonmat-hook/engines.md` 의 해당 엔진 절.
- **이벤트 이름이 번호뿐이어도 음원 파일의 이름을 본다.** 묶음 안 소리에 원본 파일 이름이 남아 있으면 훅을 실제로 재생되는 소리 단위에 건다.
- **공개 이름표에 없는 이벤트를 놓치지 않는다**: 이벤트 해시로 직접 대조한다(니어 `ev####_se`·`evb` 61개, 이름표에 없어서 컷씬이 비었었다).
- **끝까지 번호뿐인 소리는 모양으로 가른다**(`soundprep` 의 `looks_like_impact`): 2초 이하, 0.04초 안에 오르고, 30~500Hz 에 힘이 있는 것만 타격으로 보고 낮은 세기(0.6)로. 발소리처럼 번호 범위로 알 수 있는 것은 규칙으로 먼저 잡는다.
- 주인이 이름에 있는가(`pl0000_…`, `SE_PC_`, `PL_`)를 본다. 재질 이름뿐(`foot-soil`)이면 2단계에서 주인 정보(오브젝트·액터·거리)를 반드시 받아야 한다.

## 음원 꺼내기 — 훅과 같은 날 끝낸다
절차는 하나다: 찾기 → 컨테이너 열기 → 목록 → 디코딩 → 48kHz 모노. 게임별로 다른 것(파일명·경로)은 프로필 `source` 에 적는다. 리더별 노하우는 `readers.md`.

- 프로필 안의 데이터 파일(트리·레이어·이름표·규칙)은 **그 폴더 기준** 이름(`"trees.json"`), 소리 폴더는 **`sounds/<id>/` 기준** 이름(`"hap"`, `"spk"`, `"seq"`)으로 적는다(`sonmat_paths.py`). 소리·추출본은 `sounds/<id>/` 에만 쌓이고 git 이 보지 않는다.
- 리더가 없으면 `sonmat/tools/soundprep/` 에 모듈 하나를 추가하고 `READERS` 에 한 줄 넣는다.
- 아카이브는 우리 코드로 풀지 않는다. 공개 언패커를 라이선스부터 확인하고 사용자 PC 로 받아 쓴다(`sonmat/data/fetch_tools.json`).
- 추출본·키는 배포하지 않는다.
- 칸마다 "이름 수 / 게임에 있는 수 / 음원이 풀린 수"를 세어 빈 곳을 본다. 효과음 본체를 찾을 때까지 "음원을 꺼냈다"고 하지 않는다(세키로: 옆에 풀린 묶음은 음악·환경뿐, 효과음은 아카이브 안).
- **소리 준비의 거름(`source.cues`·`skip`)이 진짜 소리를 지우지 않는지** 본다. 11-02 "소리 없음" 판정 다섯 중 넷이 우리 정규식이 거른 것이었다(`AMB_OJ_*`, `skip` 의 `BGM` 이 `…_No_BGM` 을 지움).

## 남기는 것: `intake.md` 1·2·5·6절과 조작·장소 메모
항목마다 **확인됨 / 추정 / 미확인**. 양식:
1. 훅: 엔진, (2단계에서) 붙인 방법, 이벤트 줄 형식, 검증 여부
2. 이름표: 출처, 개수, 분류별 개수(타격·맞음·회피·착지·발소리·적·UI·음악·대사·컷씬)
3. 나/남 구분법 (2단계)
4. 바닥·상태 신호(스위치, RAM) (2단계)
5. 음원: 어디서 어떻게, 개수, 암호화
6. 원래 진동: 출처 전부, 순간 수, 원래 진동이 없는 내 동작, 입력 방식·실행 조건(Steam Input, 옵션)
7. 빈도 기록 유무
8. 못 한 것
