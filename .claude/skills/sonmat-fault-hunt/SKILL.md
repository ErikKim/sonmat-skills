# sonmat-fault-hunt

가끔 생기는 증상은 한 사람이 한 가설을 붙들면 그쪽 증거만 모으게 된다. 그래서 경로를 셋으로 나눠 따로 조사하고, 외부 모델(agy)에게 독립 의견을 받고, 마지막에 반박 담당이 걸러 낸다.

**실행 모드: 서브 에이전트(팬아웃 → 팬인 → 검증).** 조사자끼리 대화할 필요가 없고 결과 파일만 모으면 된다.

## 순서
1. **브리프 작성** — `dshaptics/_workspace/<조사명>/00_brief.md`. 증상의 정확한 뜻(사용자 표현 그대로), 언제부터, 무엇과 비교해 멀쩡한지, 사용자가 기각한 것, 이미 잰 것, 금지 사항. 사용자가 플레이 중이면 PC 는 읽기 전용이라고 적는다 — 시험음·마이크·HID 쓰기가 증상을 만들 수 있다(10-09 에 실제로 그랬다).
2. **조사 3갈래를 동시에**(Agent, `model: "opus"`, 백그라운드): `sonmat-audio-path`(엔진→윈도우), `sonmat-receiver-fw`(리시버 펌웨어 소스), `sonmat-evidence`(기록 대조). 각자 정의 파일(`.claude/_sets/dshaptics/agents/<이름>.md`)을 읽고 따르게 한다.
3. **agy 독립 의견** — 브리프 + 핵심 코드 발췌를 파일로 만들어 `cat <파일> | python3 .claude/skills/ask-llm/ask_llm.py --provider agy -` . 답은 `04_agy.md`. agy 에게는 다른 조사 결과를 보여 주지 않는다(독립성). 긴 프롬프트는 반드시 stdin.
4. **반박** — 1~3번이 끝나면 `sonmat-skeptic` 이 `05_verdict.md` 를 쓴다.
5. **보고** — 1순위 가설, 확신도, 가장 싼 확인 방법, 고치는 방법을 사용자에게. 확인 안 된 것은 그렇게 말한다. 고치는 것은 사용자가 하라고 한 뒤에.

## 조사 전에 — 지금까지 확인된 것 (2026-10-11 기준, 다시 캐지 말 것)
자료: `dshaptics/_workspace/spk_hunt/`(1차, 10-09), `spk_hunt2/`(2차, 10-11), `ROADMAP.md` 의 "패드 스피커 끊김" 항목.
- 증상 = 패드 **스피커 소리**가 나오다 말다 한다(찌그러짐 아님). 엔진 첫날부터.
- 끊긴 순간에도 엔진 기록은 깨끗하다(늦은 블록·언더런·한계 초과 0). 엔진의 스피커 채널은 음성을 더하기만 한다. → 차이는 리시버~패드.
- 리시버(DS5Dongle v0.7.2-hotfix)는 PC 의 USB 박자와 패드 재생 박자를 맞추지 않는다(무음 메우기·수위 관리 없음). 햅틱 크기가 스피커 처리에 닿는 길은 리시버 안에 없다. 최신 릴리스가 지금 그 버전이다.
- **1순위 가설(미확정)**: 엔진이 게임보다 먼저 열어 둔 패드 소리 스트림이 게임 시작(로딩·셰이더 컴파일)을 겪으면 나빠지고, 스트림을 다시 열면 낫는다. 세 번 같은 모양(10-09 오공, 10-11 니어·세키로). 조치 = 엔진이 게임의 첫 소리 3초 뒤 스트림을 다시 연다(로그 `pad stream opened again`). **이 로그가 찍힌 판에서도 끊기면 이 가설은 탈락** — 그때 이 스킬을 다시 돌린다. 세이브 로딩 뒤 한 번 더 여는 것은 실제로 끊기는 게 확인되면 넣기로 했다(사용자).
- 버린 것: 스피커 세기 0.2 근처 문턱(0.7 에서도 끊김), "효과를 많이 넣어서 랙", 음원 문제, 0.5초·10초 보고서, 트리거 명령.

## 실험할 때 지킬 것
- **실험을 걸려고 한 조작이 원인을 고쳤을 수 있다.** 10-11 에 "스피커가 나는 동안 진동을 15% 로" 실험을 걸려고 엔진을 다시 띄웠고, "안 끊겨"를 듣고 "겹침이 원인으로 확정"이라고 말했다. 실제로는 엔진을 다시 띄운 뒤 원래 설정에서도 안 끊겼다. 설정을 바꾸는 실험은 **원래 설정으로 되돌린 대조**까지 하고 나서 결론을 말한다. 대조 전에는 "확정"이라고 쓰지 않는다.
- 끊긴 판마다 적는다: 엔진 시작 시각, 게임 시작 시각, 스트림을 마지막으로 연 시각, 끊긴 시각, 그때 스피커로 나가던 소리와 길이.
- 사용자가 "방금도 끊겼어"라고 하면 **그 자리에서** 엔진 기록 끝을 읽는다. 나중에 찾으면 시각을 못 맞춘다.
- 증상을 줄이는 조치(진동이나 소리를 낮추기)는 진단용이다. 해법으로 내놓지 않는다("하나를 줄이니까 좀 싱겁다. 이게 답은 아닌 거 같은데").
- 기준 게임 녹음(PC `C:\Users\Public\dshaptics\ref\`)으로 "제작사는 그 순간 어떻게 보내나"를 잴 수 있다(스텔라 블레이드: 스피커가 난 시간의 73% 가 센 진동과 겹침, 스피커 신호 최대 0.09).
- 질문이 하나로 좁혀져 있으면 세 갈래를 다 띄우지 않고 그 갈래 하나만 띄운다(10-11: 리시버 펌웨어 담당 하나). 조사 도중 전제가 바뀌면 그 조사자에게 바로 알린다.

## 에러 핸들링
조사 하나가 실패하면 한 번 다시 돌리고, 또 실패하면 빠진 채로 반박 단계로 간다(보고에 누락 명시). agy 가 빈 답이면 래퍼가 재시도한다 — 그래도 없으면 `04_agy.md` 에 "응답 없음"만 남긴다. 조사자끼리 결론이 다르면 지우지 않고 둘 다 반박 담당에게 넘긴다.

## 테스트 시나리오
- 정상: 브리프 → 세 보고서 + agy 의견 → 판정표에 6조건 판정이 가설마다 채워짐 → 1순위와 확인 방법이 나옴.
- 에러: PC 가 꺼져 있음 → 조사자들이 "PC 미확인"으로 쓰고 코드·소스·맥 사본만으로 진행, 판정표의 확신도가 낮게 나옴.
