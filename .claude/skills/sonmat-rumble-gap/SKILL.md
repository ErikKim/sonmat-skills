# sonmat-rumble-gap — 4. 원래 진동 빈자리 대조

목표는 **원래 진동 − 우리 진동**만 살리는 것이다. 원래 게임이 진동하는데 우리가 조용한 순간을 채우고, 우리가 울리는데 원래 게임이 진동할 근거가 없는 것은 의심한다. 원래 진동 자료는 **어느 순간이 진동하나의 근거로만** 쓴다 — 파형·세기는 원음이나 우리 틀로.

이 단계가 품질을 가장 많이 올렸고(P의 거짓 장치·문 236개, 오공 변신 132개·적 충격 364개, 아캄 8줄), 가장 크게 망친 적도 있다(11-04 이름만 보고 넣은 표, 분당 진동 64 → 284). 차이는 **근거가 원래 진동이었나, 이름이었나** 하나다.

## 입력
- **원래 진동 표**: 1단계(`sonmat-read-files`)가 찾은 것. `sonmat-video/data/rumble_research/<게임>_*.json`, `_<게임>_rea/`, `intake.md` 6절. 없으면 1단계의 "원래 진동 표 찾기"부터.
- **엔진이 실제로 울릴 목록**: `trees.json`(진동 클립이 있는 소리)·`trees_seq.json`(컷씬)·규칙(`rules` 정규식)·`rules_auto.json`. **이름이 프로필 JSON 어딘가에 있다고 덮인 게 아니다** — 오공에서 이름표(`event_ids.json` 15,212개) 때문에 "빈자리 71"로 셌는데 엔진 기준으로는 428이었다.
- 저장소 판과 PC 판(`sounds/<id>/trees.json`, 엔진이 먼저 읽는다)이 같은지 먼저 본다.

## 짝짓기: 원래 진동 순간 ↔ 그 순간의 소리
게임 파일 안에서 같은 자리를 찾는다. 플레이·녹화를 시키지 않는다.
- 언리얼: 몽타주의 진동 표식 시각과 같은 몽타주의 소리 표식(시각 차 작게), 블루프린트·시퀀스의 진동 노드와 같은 흐름의 큐(P의 거짓 `lop_cmp.py`).
- Wwise: 이벤트의 동작 목록에 진동(`Motion_*`) 동작과 소리 동작이 같이 있으면 짝(오공 `bnk_motion.json`).
- 프롬: 동작 파일(`.tae`)의 진동 이벤트와 같은 동작의 소리 이벤트, 패드 표 번호 대조(세키로 `sek_cmp/`). 번호 일치는 "추정"으로 적는다.
- UE3: 애니·전투 스크립트·Kismet·영상 표(아캄 `_arkham_rea/`).
- 하드코딩된 진동(rea 로 찾은 호출처): 그 조건에 나는 소리가 있는지(니어 내 피격 = 기준 이상 데미지).
- 이미 쌓인 기록(원래 진동 로그 `rumble_<exe>.log`, 녹화)이 있으면 확인용으로 쓴다(오공: 원래 진동이 그 이벤트 0.01초 안에 켜짐).

## 가르기
원래 진동 순간마다 하나로 가른다. 개수를 표로 남긴다.

| 가름 | 할 일 |
|---|---|
| 덮임 — 엔진이 그 소리로 울림 | 없음 |
| 소리 있음, 규칙 없음 | 규칙 한 줄(칸·파형). 적 소리도 원래 게임이 패드를 울렸으면 넣는다(오공 적 충격 223) |
| 소리 있음, 규칙은 있는데 클립이 안 만들어짐 | 소리 준비의 거름을 고친다(`source.cues`·`skip`·`long`). P의 거짓 138개가 이랬다 |
| 긴 소리 안의 한 순간 | `source.long` + `source.moments`(크레인 8.38초 충격) |
| 소리 없는 진동 | `ffb.kinds`(원래 진동이 오는 순간 우리 파형) 또는 같은 순간 다른 소리로 이미 울리는지 확인. 컷씬 안의 소리 없는 진동은 파형을 가져올 수 없으니 뺀다 |
| 발소리·옷 소리뿐 | 넣지 않는다 |

- **"소리 없음"은 원본에서 다시 확인한 뒤에만** 판정한다. 11-02 "소리 없음" 다섯 중 넷이 틀렸다(우리 정규식이 거름, 공개 이름표에 없음, `skip` 의 `BGM` 이 `No_BGM` 을 지움).
- 내 쪽 소리를 표로 넣을 때는 `rules_auto.json` 에 `"why": "orig_motion"` 을 붙여 근거를 남긴다(오공 371개).

## 반대 방향: 근거 없는 진동 덜어 내기
- 우리가 울리는 소리마다 **원래 진동 동반률**(그 소리가 날 때 원래 게임이 진동하는 비율)을 본다. 무작위 수준(P의 거짓 12%)이면 사건처럼 보이는 이름이라도 동작에 따라 나는 옷 소리다(`Fall_Land_Rustle`·`Rustle_Sit`·`Item_Fail_Rustle` 6~41%). 가드 피격처럼 100%인 것이 근거 있는 것.
- 원래 진동이 없는 내 동작(명중·회피·발소리)은 우리 칸의 몫이라 동반률로 덜지 않는다.
- **되돌릴 때도 통째로 하지 않는다**(11-09): 커밋째 되돌리면 같이 들어간 진짜 빈자리(오공 변신 132, P의 거짓 장치·문 236)까지 빠진다. 항목마다 원래 진동 근거로 남길지 고른다.

## 확인하고 넘긴다
- 전후 **분당 진동 수**를 이미 있는 기록으로 다시 돌려 비교한다(엔진 재생). 크게 늘었으면 늘어난 상위 이름부터 본다.
- 원래 진동만 있는 시간 비율이 줄었는지(P의 거짓 1.5 → 0.3%).
- `soundprep` 로 새 클립만 만들고(`--new`), 새 규칙 소리가 전부 클립이 됐는지 센다.
- `intake.md` 6절에 출처·순간 수·가름별 개수·추가한 줄을 적는다. `WORKLOG.md` 에도.
