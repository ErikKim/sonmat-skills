<날짜>. <새 게임 / 스킬 시험판(완성본은 맨 끝 비교 때만 연다)>. 항목마다 **확인됨 / 추정 / 미확인**을 붙인다. 단계마다 자기 절만 채운다(1단계 = 1·2·5·6·7절과 조작·장소, 2단계 = 1·3·4절, 3단계 = 8절, 4단계 = 6절 끝, 스킬 시험 = 9절).

## 1. 훅 (1·2단계)
- 엔진: <Wwise / 언리얼 자체 오디오 / FMOD Ex / 유니티 / MAME>, 근거(실행 파일 문자열·파일).
- 붙인 방법: <DLL·UE4SS·BepInEx·MAME 플러그인>, 새로 붙였나 / 검증된 것 재사용.
- 이벤트 줄 — **실제 줄 예 서너 개를 그대로**: 경로가 붙는가, 접미(`_Cue`)가 붙는가, 이름 줄과 번호 줄(`wid:`)이 따로 오는가, 어느 줄기가 주(`native.main`)인가, 한 줄기로만 오는 내 소리(명중)가 있는가.
- 검증: <게임 안에서 줄이 오는 것을 봤나, 기록 줄 수>.

## 2. 이름표 (1단계)
- 출처·개수(공개 이름표 / 게임 파일 큐 이름 / 번호뿐).
- 분류별 개수: 내 캐릭터(휘두름·명중·회피·착지·발소리·기술·도구·아이템) · 적 · 컷씬 · 환경 · UI · 음악 · 대사.
- 크기·재질 이름 규칙(S/M/L, 재질).

## 3. 나/남 구분 (2단계)
- 주인 정보(액터·오브젝트·접두어·거리·패드). 이름과 주인이 어긋나는 소리. 동료·적과 이름을 같이 쓰는 소리. "없음"이면 그렇게 쓰고 대체 수단.

## 4. 바닥·상태 신호 (2단계)
- 바닥이 어떻게 오나(발소리 이름 / 스위치 훅 / 없음). 소리 끝을 받는가. 장착·탈것·날씨 같은 이어지는 상태를 알리는 소리.

## 5. 음원 (1단계)
- 어디에 어떻게(pak·bnk·cpk·fsb·롬), 키·암호, 개수, 리더 이름. 칸마다 "이름 수 / 게임에 있는 수 / 음원이 풀린 수".

## 6. 원래 진동 (1단계, 4단계가 끝을 채움)
- 출처 전부(데이터 표·코드 호출처), 순간 수, 표 파일 위치(`sonmat-video/data/rumble_research/<게임>_*.json`).
- 원래 진동이 **없는** 내 동작(우리 칸이 채울 자리).
- 입력 방식·실행 조건(XInput 전용 → Steam Input, 듀얼센스 직접 지원).
- (4단계) 가름별 개수: 덮임 / 소리 있음·규칙 없음 / 규칙 있음·클립 없음 / 긴 소리 안 순간 / 소리 없는 진동 / 발소리·옷 소리뿐. 더한 줄, 덜어 낸 줄.

## 7. 빈도 기록 (1단계)
- 쓸 수 있는 기록(`collect_<id>.log`·`hapticsd.log`)의 위치와 길이. 없으면 "없음 — 빈도 미확인".
