# sonmat-new-game — 입구

새 게임 하나를 **사용자가 켜서 느껴 볼 수 있는 판**까지 한 번에 가져간다. 목표 수준은 "1차본이 있다"가 아니라 **완성 프로필과 같은 층이 다 들어 있다**이다. 완성본 = `sonmat-game-liesofp/haptics.json`(언리얼, 손 무기·트리거·원래 진동 재현·비), `sonmat-game-wukong/haptics.json`(Wwise, 바닥 스위치·구름 탈것·환경 스침·내 타격 대리). 1차본을 넘기기 전에 이 둘과 나란히 놓고 빠진 층을 본다.

## 다섯 단계

| 단계 | 스킬 | 언제 | 받는 것 | 남기는 것 |
|---|---|---|---|---|
| 1. 게임 파일 읽기 | `sonmat-read-files` | 게임을 켜지 않고 | PC 설치 폴더 | 엔진·이름표·음원(`sounds/<id>/`)·**원래 진동 표**·리더 → `intake.md` 1·2·5·6절 |
| 2. 훅 | `sonmat-hook` | 게임을 켜서(타이틀) | 1의 엔진·함수 실마리 | `hook.json`, 검증된 이벤트 줄, 나/남 구분, 바닥·소리 끝 신호 → `intake.md` 1·3·4절 |
| 3. 1차본 | `sonmat-first-draft` | 패드 없이 | `intake.md` | `game.json`·`haptics.json`·클립, PC 반영 |
| 4. 원래 진동 빈자리 대조 | `sonmat-rumble-gap` | 1차본 직후, 이미 붙은 게임도 언제든 | 원래 진동 표 + 엔진이 울릴 목록 | 빠진 순간 추가, 근거 없는 것 제거, `intake.md` 6절 |
| 5. 첫 판 뒤 다듬기 | `sonmat-tune` | 사용자가 해 보고 말해 줄 때 | 그 판의 엔진·이벤트 기록 | 프로필 고침, 일반화되면 `calibrations.md` |

- **"새 게임 붙여"로 시작했으면 1 → 4까지 멈추지 않고 이어 간다.** 단계 사이에서 사용자에게 넘기지 않는다. 멈추는 곳은 두 군데뿐이다: 안티치트(아래 거르기)와 훅 첫 연결(게임을 타이틀에 켜 둬야 한다 — `sonmat-hook`).
- **5는 사용자가 플레이해야 시작된다.** 플레이를 숙제로 내지 않는다. 4까지 끝낸 판을 넘기고, 사용자가 해 보고 말해 주면 그때 5.
- 단계 스킬을 하나만 불렀으면 끝에 **다음 단계를 한 줄로 제안**한다(각 스킬 끝의 "다음" 절).
- 기준 게임 대조(`sonmat-ref-study`)는 어느 단계에서든 "이 상황의 결을 무엇으로 고르나"가 막히면 부른다. 장치 끊김은 `sonmat-fault-hunt`.

## 시작 전에 거르기
1. **대상인가**: 안티치트·온라인으로 막힌 게임만 뺀다. 듀얼센스를 이미 지원하는 게임도 보강 대상이다. 사용자가 가진 게임인가.
2. **안티치트**가 있으면 접는다고 먼저 말한다. 오프라인 전용으로 돌리는 길이 있어도 사용자 결정 사항이다.
3. **손 프리셋인가, 자동 생성인가**: 이 스킬은 손 프리셋(사람이 게임을 읽고 만드는 판)이다. 앱의 자동 생성(`tools/gamesetup/autosetup.py`)은 "지금 도구로 되는 조합은 규칙으로 자동"이 원칙이라 게임별로 손대지 않는다. 자동 생성이 안 되는 게임에 새 도구를 만드는 것은 사용자가 손 프리셋으로 하자고 할 때만.

## 어디에 무엇이 있나 (`sonmat-prj/` 기준)
- 규칙·상태·다음 할 일: `sonmat/WORKLOG.md`(맨 위 "규칙"이 SSOT)
- 엔진 `sonmat/hapticsd.py` + `sonmat/tools/engine/`(프로필 키를 읽는 곳 = `profile.py`), 음원 준비 `sonmat/tools/soundprep/`, 엔진 비교 `sonmat/tools/enginetest.py`
- 모델 `sonmat/data/model.json`, 트리거 프리셋 `trigger_presets.json`, 거친 정도 표 `haptic_templates.json`
- 프로필: 게임 레포 `sonmat-game-<id>/`, 만드는 중이면 `sonmat-maker/profiles/<id>/`. `haptics.json`(느낌)·`hook.json`(연결)·`game.json`·`intake.md`
- 원래 진동 자료·대조 스크립트: `sonmat-video/data/rumble_research/`, 실행 파일 분석: `sonmat-prj/_<게임>_rea/`

## 보조 도구
| 도구 | 어느 단계 | 무엇에 |
|---|---|---|
| rea (스킬 `reverse-engineer-anything`) | 1, 2, 4 | 실행 파일에서 소리 함수·진동 함수와 그 호출처 찾기, 인자 형식 확인, 32비트·포장된 exe. 니어 원래 진동 출처 전수(`_nier_rea/`), 아캄 패키지 표(`_arkham_rea/`) |
| GPT (`ask-llm --provider codex`) — **권장** | 3, 4 | 칸 배정표·층 체크를 넘겨 빠진 층과 잘못 걸린 이름을 묻는 두 번째 의견. 판정은 우리가 한다 |
| 에이전트 `sonmat-ref-reader`·`sonmat-ref-gap` | 3, 5 | 기준 게임 규칙 읽기·우리 것과 맞대기(`sonmat-ref-study` 가 부름) |

## 사용자가 다른 게임을 하는 중이면
- 엔진을 다시 띄우지 않는다. 새 프로필은 다음 엔진 시작 때 읽히니 파일만 놓아 둔다.
- PC 의 무거운 일(음원 디코딩)은 낮은 우선순위로 돌린다(`start "" /belownormal /b /wait`).
- 패드·오디오 장치는 건드리지 않는다. 훅 시험은 무음 출력의 별도 프로세스에서만.

## 모든 단계 공통 — 하지 말 것
- 사용자에게 수집용·확인용 플레이를 숙제로 내지 않는다. "알아서 해"는 끝까지 만들라는 뜻이다. 게임을 대신 조작하라는 뜻도 아니다.
- **근거는 게임 파일 정적 분석으로.** 플레이 기록·녹화는 이미 있는 것만 쓴다. "어렵다"로 미루지 말고 파일 → exe 까지 끝까지 간다.
- 사용자가 플레이 중일 때 패드에 시험음·HID 를 쓰지 않는다. 화면 캡처도 하지 않는다. PC 는 읽기만.
- 붙여 보지 않은 훅을 "된다"고 하지 않는다. 느껴 보지 않은 값을 "맞췄다"고 하지 않는다.
- **이름만 보고 진동 소리를 대량으로 넣지 않는다**(11-01 리스크 오브 레인 2, 11-04 네 게임 — 두 번 실수). 넣는 근거는 원래 진동·실제 재생·사용자 요청.
- 원래 게임의 진동 파형·세기를 가져다 쓰지 않는다. "어느 순간이 진동하나"의 근거로만.
- 한 게임에서 나온 문제를 그 게임만 고치고 끝내지 않는다. 같은 구조의 다른 게임에도 있는지 본다. 고치는 곳은 공통 규칙(엔진·소리 준비), 게임 몫은 프로필 몇 줄.
- 커밋은 사용자가 말할 때만.

## 테스트 시나리오
- 정상: "다음 게임 니어 오토마타" → 거르기 → 1 파일 읽기(엔진 Wwise·이름표 8,582/11,712·원래 진동 `VibTrack`) → 2 훅(타이틀에서, 이벤트 줄 확인) → 3 1차본(층 체크까지, PC 반영) → 4 빈자리 대조 → "켜서 해 보세요, 이건 아직 비어 있어요" 로 넘김.
- 에러: PC 가 꺼져 있음 → 1 은 검색으로 엔진·이름표만 확인하고 멈춰서 알린다(깨우지 않는다). 훅이 게임을 죽임 → 사실대로 알리고 원인을 고친 뒤 타이틀에서 다시. 음원 리더가 없음 → 리더를 만든다(손 프리셋에선 그게 일의 절반이다).
